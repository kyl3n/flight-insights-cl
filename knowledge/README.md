# Knowledge pack

Versioned data the engine reads, updatable without an app release (spec: System architecture). Everything here is generated by the tools in `tools/` from ArduPilot's own sources, except the curated rules, which say why they exist.

| Path | What it is | Made by |
| --- | --- | --- |
| `manifest.json` | Which releases the pack covers, and the ArduPilot commit each came from | `tools/build_param_metadata.py` |
| `params/<version>/copter.json.gz`, `plane.json.gz` | Every parameter of a release: name, display name, description, units, range, values, bitmask, user level and flags (reboot required, read-only, volatile, calibration). Copter includes helicopters, Plane includes QuadPlanes. | `tools/build_param_metadata.py`, which runs ArduPilot's `param_parse.py` |
| `params/renames.json` | Parameters renamed between releases, each with its proof | `tools/find_renames.py` |
| `params/classes.json` | How parameters are classed: tuning, calibration, learned, counter, hardware, ground station | Curated |
| `boards/<version>.json` | Every ChibiOS board's logged short name with its MCU, MCU family (F4, F7, H7...) and bootloader board ID | `tools/build_boards.py`, from the release's `hwdef` files and `board_types.txt` |
| `setup/platform.json` | The guided platform setup: its ten steps and every field, in English and Ukrainian, each saying why it is asked and, if required, what a gap prevents | Curated |
| `rules/archetypes.json` | Rule pack v0 for the archetype scorer: weighted conditions on fingerprint features, each with its reason; marked uncalibrated | Curated |
| `rules/hover.json` | When a multirotor, helicopter or QuadPlane in VTOL flight counts as hovering steadily; starting values, marked uncalibrated | Curated |
| `rules/logging.json` | Which log messages the analyzers need and which `LOG_BITMASK` bits log them, per vehicle, plus the `INS_RAW_LOG_OPT` bits; each read from the named release's source | Curated |
| `metrics/*.json` | The metric registry: every metric and finding the analyzers produce, with its definition, method, unit, direction, zones and their sources, and its wording in English and Ukrainian. The engine refuses an entry with any of that missing | Curated |
| `enums/<version>.json` | Flight-mode names per vehicle, log-event names, error subsystems and codes, and internal-error bits, by the numbers logs record (MODE.ModeNum, EV.Id, ERR.Subsys and ERR.ECode, PM.InE) | `tools/build_enums.py`, from the release's `mode.h`, `AP_Logger.h` and `AP_InternalError.h` |

## Adding a release

```sh
python3 knowledge/tools/build_param_metadata.py ~/ardupilot-4.7.3 4.7.3
python3 knowledge/tools/find_renames.py ~/ardupilot-4.7.2 ~/ardupilot-4.7.3 4.7.2 4.7.3
python3 knowledge/tools/build_enums.py ~/ardupilot-4.7.3 4.7.3
python3 knowledge/tools/build_boards.py ~/ardupilot-4.7.3 4.7.3
```

`find_renames.py` records a rename only with proof from both releases' source: the old and the new name are stored in the same place in the parameter tables (same group, index and variable), so the value carries over unchanged. It lists every other removed or added parameter for review. A rescale, where the units change and the firmware converts the value, always needs a person. That person adds the entry by hand, with `scale` and an `evidence` that cites the conversion code. The engine's tests reject any entry without evidence.

## Licensing

The parameter metadata, the mode and event names and the board table are generated from ArduPilot's GPLv3 source (documentation comments, enums and board definitions), as ArduPilot does for ground stations. Shipping it with the app is on the spec's list of items for legal review.
